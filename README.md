# 剧场灯光排程台（离线本地账）

给地下库房排练用的灯光排程前端：演出、灯具、Cue 共用一份保存在浏览器本地的账，
断网能续作、断电不丢；多名灯光师各改一份控台副本，回主控台按「先到入库、晚到列冲突」合并。

## 能力对照

- **一份本地账**：演出 / 通道（额定负载）/ 灯具 / Cue / 控台副本 / 变更单 / 发布记录全部存入 `localStorage`（`lighting-console-ledger-v1`），随时可导出 JSON 备份。
- **通道额定负载**：每通道登记额定功率；Cue 的负载占用按「灯具功率 × 亮度」逐通道汇总，超额定在 Cue 卡片与通道校核表标红。
- **灯位/色片变更作废旧 Cue**：灯具一旦改了舞台坐标或色片，引用它的 Cue 立即置脏，触发顺序与负载占用显示为「已作废·待重算」，且暂不计入通道校核；重算后按 Cue 号重排触发顺序、恢复负载计算。
- **两人同改一场演出**：副本带基线版本号（`baseRev`）。提交时做三方合并（建副本快照 / 主账当前 / 晚到提交）——先到的整份入库；晚到提交里无冲突的操作先入库，字段级冲突（原值/主账/晚到三列）列给主控台操作员逐条裁决。
- **权限**：主控台操作员可直接改主账、裁决冲突、发布；灯光师主账只读，改动只能在「控台副本」里进行，提交后进入待审稿，由操作员发布。
- **断网续传**：断网提交进入发件箱，联网后按提交序号自动重试；每个操作带幂等键（`opId`），已合并内容重试时自动跳过、绝不重复。
- **旧数据迁移**：首次打开自动把旧版静态 Cue 表（Cue 12 冷蓝侧光 / Cue 18 追光入场 / Cue 24 暖色谢幕）解析迁入演出、灯具（含 CH 021–028）和 Cue；缺失的通道额定负载、灯位、功率、色片等字段标「待补」，留待补全后再发布。
- **演示**：「控台副本」页有「模拟两名灯光师同改一场后同时提交」按钮，一键制造先到/晚到冲突。

## 技术栈

React 19 + Vite + TypeScript，无额外运行时依赖；本地存储用 `localStorage`。

## 本地运行

```bash
npm install
npm run dev
```

开发端口：62002

## 代码结构

```
src/
  types.ts                 本地账数据模型（演出/通道/灯具/Cue/副本/变更单/发布）
  ledger.ts                持久化、负载校核、作废重算、三方合并、冲突裁决、发布
  migrate.ts               旧版静态记录首次迁移与字段待补标记
  App.tsx                  顶栏（联网开关/身份切换/演出切换）、三个主标签页
  components/
    StageMap.tsx           舞台平面灯位图（拖拽灯位、当前场景点亮预览）
    LedgerView.tsx         灯具筛选表、通道负载校核、Cue 触发顺序与占用
    Editors.tsx            演出/通道/灯具/Cue 表单（待补字段高亮）
    CopiesTab.tsx          控台副本：拉副本、断网编辑、提交、对齐主账
    ReviewPanel.tsx        发件箱重试、字段冲突裁决、待审稿与发布
```
